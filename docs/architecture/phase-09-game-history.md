# Phase 9 — Persistence and replay (durable game history)

Status: done, branch `phase-9-game-history`, 2026-09-13. Two independent
reviews (correctness/concurrency, security) ran against this phase; their
findings and fixes are included below.

Historical snapshot of the game-history subsystem as it stood when this
phase (including its review fixes) completed. Not updated for later
changes — see `docs/architecture/latest_architecture.md` for the current
state, and `docs/games.md` for the living documentation.

## What was built

`DECISIONS.md` §12: "the event log is the source of truth; finished games
replay from it." This phase is what actually makes that true durably: two
Postgres tables and the HTTP surface over them, since the live `EventBus`
(Redis Streams or in-memory) is a transport, not durable storage, and does
not survive a Redis flush or a process restart.

- **Schema** (`app/models.py`): `GameRecord` (`game_record`, primary key =
  the referee's own `game_id` rather than a fresh id, so
  `correlation.game_id` on every event ties straight back to this row; FK
  to `room.id`, `CASCADE`) and `GameEvent` (`game_event`, FK to
  `game_record.id`, `CASCADE`, unique on `(game_id, seq)`). Migration
  `f54e8ebd4583_game_history_phase_9.py` autogenerated cleanly against the
  two new tables only.
- **`RoomService._archive_game`**, hooked into `_finish_room`
  (`GameRunner`'s completion callback, from Phase 7). When a game ends, it
  reads the room's full event history off the live bus, keeps only events
  carrying a `correlation.game_id` (everything the referee published,
  including its own `room.stopped` on cancellation — `RoomService`'s own
  `room.created`/`room.seat_filled` carry no `game_id` and are excluded),
  builds one `GameRecord` from the `game.started`/`game.finished`
  payloads, and archives every kept event as a `GameEvent`. Plus
  `get_game_record`/`list_game_records`/`game_events` read methods.
- **`app.rooms.guard.resolve_subscriber`**: the HTTP-layer admission
  wrapper around Phase 7's `subscription_guard`, moved here (made public)
  from a private helper in `app/api/routes/rooms.py` so the new `/games`
  routes reuse the exact same room-admission check the live `/events`
  route already uses — one place, not two that could drift.
- **`app/api/routes/games.py`** (new router, prefix `/games`):
  `GET /{game_id}` (summary), `GET /{game_id}/events` (the durable
  counterpart to the live route — same `filter_for_subscriber` call,
  reconstructing an `EventEnvelope` from each archived row),
  `GET /{game_id}/replay?seat=&upto=` (rebuilds one seat's `PlayerView` at
  any point via `Referee.replay`, from Phase 3, truncating the archived
  move log to `upto` moves; same own-seat-only privacy rule as the live
  `/view`).
- **Deferred, precisely**: no retry/backlog for a failed archive (logged,
  not re-attempted); no pagination past a generous `limit=100_000` on
  either the live-bus read or the archived-row read.

## Key implementation decisions made during this phase

- **The status write and the archive write are two separate steps, and
  that separation is load-bearing.** `_finish_room` only *writes*
  `room.status` when it is still `"in_progress"` — an explicit `stop()`
  call races this exact callback (both await the same cancelled task;
  either can resume first) and whichever already wrote `"stopped"` must
  not be double-written. But the callback still fires exactly once per
  game regardless of who won that race, so **archiving is never nested
  inside that status guard** — it always runs, independent of the race's
  outcome.
- **`/games`, not `/rooms/{room_id}/games/...`**: a `game_id` is already
  globally unique and self-sufficient — a client that only knows a
  `game_id` (a future leaderboard listing, say) shouldn't need to also
  know its `room_id` to look it up. Every route resolves `room_id` from
  the `GameRecord` internally before running the identical admission check
  `/rooms/{room_id}/events` uses, so this design costs nothing in either
  security or consistency.
- **An explicit `session.flush()` between adding the `GameRecord` and
  adding its `GameEvent` rows**, rather than relying on SQLAlchemy's flush
  planner to infer the dependency order — the two models have no
  `Relationship()` between them for the planner to infer from, and the
  insert order matters for the foreign key.

## Review-caught-by-self bug (before this ever reached a reviewer)

The first draft nested `_archive_game` *inside* `_finish_room`'s "only
write if still `in_progress`" guard — meaning archiving was silently
skipped every time `stop()` happened to win the race described above.
Caught by writing (and running) `tests/rooms/test_game_history.py` before
considering the phase done: HTTP-level "stop a room, check it archived"
tests happened to pass either way depending on real scheduling order, so a
dedicated deterministic regression test was added
(`test_finish_room_archives_even_when_stop_already_won_the_status_race`)
that constructs the room already `"stopped"` — simulating `stop()` having
already won — *before* calling `_finish_room`, which fails against the
original nested version and passes against the fix. Verified both
directions by hand: temporarily reintroducing the buggy guard confirmed
the test fails with the expected `LookupError`, then the fix was restored.

## Review fixes (two independent reviews: correctness/concurrency, security)

- **Agent-published events never archived (HIGH, correctness)**: unlike the
  bug above, this one wasn't self-caught. `AgentController._publish`
  stamped no `correlation` at all, so every `agent.reasoning`,
  `agent.turn_metrics`, and agent-authored `chat.message` was silently
  dropped by `_archive_game`'s `correlation.game_id` filter. Root cause:
  `AgentController` is constructed before `Referee.__init__` generates its
  `game_id`, so it had nothing to stamp with at construction time. Fixed
  by threading it through: `AgentController` gained a
  `game_id: str | None` attribute (starts `None`); `Referee.__init__`
  duck-type-sets it on any controller declaring the attribute (the same
  pattern the existing `say`/`hear` hooks already used) right after
  generating its own `game_id`.
- **Inconsistent 404 message between "unknown game" and "game exists but
  room denies you" (LOW, security)**: two different `detail` strings for
  the same status code let a caller who already holds a `game_id`
  distinguish the two cases — a one-bit side channel. Fixed with a shared
  `_admitted_record` helper unifying both failure branches to the
  identical `"Game not found"` 404 across all three routes.
- **Archiving completeness depends on the live bus's own retention
  (MEDIUM, correctness, documented not code-changed)**: both `EventBus`
  implementations bound each room to `EVENT_STREAM_MAXLEN` (10,000)
  events; `_archive_game` only sees whatever is still there when the game
  ends. Left as a documented dependency (`docs/games.md`) rather than a
  code change — ten thousand events is enormous headroom for any of these
  games' actual lengths, and the cleaner fix (archive incrementally during
  play) is future work, not urgent.
- **Reviewed and accepted as-is (no change needed)**: the explicit
  `session.flush()` is correct and sufficient (the whole archive is one
  transaction — a later failure rolls back the `GameRecord` insert too);
  `replay`'s unfiltered fetch of `game.move_applied` rows is safe because
  that event type is always published `PUBLIC`; no realistic IDOR risk via
  `game_id` (a 122-bit `uuid4().hex`, and every route re-derives `room_id`
  and re-checks admission regardless); the three `/games` GET routes
  carrying no rate limit matches every other read-only room route in this
  codebase, not a gap introduced here.
- **Full suite after fixes: 753 tests, gate clean.**

## Tests and what was verified

14 new tests initially (`tests/rooms/test_game_history.py`) against a real
stopped `uno_classic` game (real `GameRunner`, real Postgres): archiving
correctness (record fields, event filtering, seq ordering), the race
regression described above, auth-gate/404 smoke tests per route,
event-visibility redaction (a non-privileged seat never sees another
seat's archived `game.view_updated`; the creator sees both), pagination
via `next_since`, and replay's own-seat-default / cross-seat-403 /
no-seat-400 / upto-422 paths. Full suite at that point: 751 tests. After
the review-fix pass above: **753 tests**, ruff/ruff-format/mypy strict/ty
all clean.
